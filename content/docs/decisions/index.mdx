这里是本项目所有实际 ADR（Architecture Decision Record）的唯一归档位置。每个文件记录一个已经提出、批准或被替代的重要选择；它们按创建日期保存在本目录中，而不是散落在 Issue、方案页或聊天记录里。

## 新建一份 ADR

1. 先判断该选择是否会影响预算、施工、网络边界、安全、体验或长期维护；需要时先创建或关联 Issue。
2. 在本目录新建 `YYYY-MM-DD-主题.mdx`，例如 `2026-08-03-iot-vlan-isolation.mdx`。
3. 使用[决策记录规范](/docs/guide/decision-log/)中的模板，写清背景、备选方案、决定、影响、回滚和验证方式。
4. 将文件名（不带 `.mdx`）加入同目录 `meta.json` 的 `pages` 列表，放在 `index` 后面，最新记录优先。
5. 通过 Pull Request 评审。获批后，在相关 Issue、方案、图纸、台账和验收记录中链接该 ADR。

## 档案规则

| 规则 | 目的 |
| --- | --- |
| 一个决定一个文件 | 让背景、证据与结论可独立引用 |
| 使用日期文件名，目录保持扁平 | 路径稳定，便于按时间检索 |
| 状态写在正文，不移动文件 | 提议、批准和替代过程都能保留历史链接 |
| 新决定替代旧决定，而不是重写旧文件 | 防止失去当时的约束、理由和责任人 |
| ADR 必须关联 Issue；实施文档必须回链 ADR | 把待办、决定和最终实现串成可复核闭环 |

<Callout title="当前档案为空">

首份 ADR 创建后，将它登记到本目录的 `meta.json`，它会自动出现在左侧“决策档案”导航中。不要用示例内容冒充已批准的项目结论。

</Callout>

## 如何查找

- 想知道目前为什么采用某项方案：先在本组导航或全文搜索中找 ADR，再打开关联的实施文档。
- 想推进一个待决定问题：在 Issue 中收集现场事实和备选方案；形成取舍后新建 ADR。
- 想修改既有决定：创建新的 ADR，并将旧记录标为“已替代”，而不是覆盖原文件。

需要字段模板、状态含义和变更规则时，请阅读[决策记录规范](/docs/guide/decision-log/)。
