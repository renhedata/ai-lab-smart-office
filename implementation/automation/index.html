自动化场景

以场景而不是设备为中心设计、测试和维护自动化规则。

在 GitHub 上编辑

本页定义自动化规则的优先级、触发条件、恢复方式和验收标准。设备架构与逐房间点位见智能化总体方案。

控制优先级

当多条规则同时满足时，按以下顺序执行：

  1. 生命安全与设备保护：消防、应急、漏水、高温、电机互锁。
  2. 现场手动操作：墙面开关、窗帘开/停/关、机房本地控制。
  3. 显式场景：会议、演示、活动、清扫、加班。
  4. 人员存在与环境规则：自动灯、自动遮阳、空调节能。
  5. 时间表与优化规则：上班预热、下班节能、日光补偿。

高优先级操作发生后，低优先级规则应暂停；不得出现“用户刚关灯，自动化立即重新开灯”的反复控制。

自动化通用约束

  1. 单个传感器离线时不得直接判定“无人”；使用最后状态、相邻传感器或保守超时。
  2. 用户手动操作必须产生可见反馈，并记录覆盖开始与结束时间。
  3. 窗帘连续动作之间设置保护间隔，开与关输出必须硬件或软件互锁。
  4. 空调只调整模式和设定值，不使用频繁断电实现节能。
  5. 摄像头不得用于卫生间或以工位行为分析替代普通存在传感器。
  6. 关键告警必须同时具备本地声光或独立保护，平台通知只作为补充。

验收测试

  • 平台在线时，墙面开关、传感器、网页和场景控制均符合优先级。
  • Home Assistant 停机后，所有灯和窗帘仍可现场操作。
  • IoT 网络中断后，不出现灯光反复开关、窗帘持续动作或空调异常启停。
  • 每个区域连续办公半天，无人员静坐导致的误关灯。
  • 手动覆盖期间自动规则不会抢回控制权，覆盖结束后能恢复自动模式。
  • 窗帘连续执行开、停、关和断电恢复测试，无正反转同时输出。
  • 下班、加班、清扫、节假日和临时活动均有明确退出方式。
  • 告警包含设备、房间、时间、当前值和处理建议，并能确认关闭。

先测试再上线

自动化第一次启用时应设定不少于两周的观察期，先记录建议动作，再逐步开放自动执行。涉及门禁、消防、燃气、应急照明和人身安全的系统不得由普通自动化规则直接控制。
