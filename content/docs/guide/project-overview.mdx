## 项目愿景

把办公室改造成一个稳定、可维护、可扩展的智能工作环境：基础网络可靠，照明与环境可自动控制，设备与空间状态可感知，每位同事都能提出问题并查看处理结果，所有重要改造都能从需求追溯到试点、决策和验收。

<Callout type="warn" title="当前状态：准备中">

现有技术文档是规划基线，不是已批准的采购或施工方案。五条工作流负责人、内部快速反馈渠道、首个试点范围和数据负责人尚未确定。

</Callout>

## 建议范围

| 工作流 | 核心交付物 | 负责人 |
| --- | --- | --- |
| 空间与需求 | 分区图、使用场景、点位需求 | 待指定 |
| 网络与弱电 | 网络拓扑、IP/VLAN 规划、布线点位表 | 待指定 |
| 智能化 | 设备选型、自动化规则、控制面板 | 待指定 |
| 采购与施工 | 预算、采购清单、施工计划 | 待指定 |
| 验收与运维 | 验收表、设备台账、故障手册 | 待指定 |

另设一名 **项目协调人**，负责接收低门槛反馈、给出编号、分流、催办和发布月度回顾；技术负责人不应同时垄断需求定义和验收。

## 阶段建议

1. **发现与需求基线**：收集员工体验、现场观察和工单，测量网络、电力、环境和任务耗时；先证明问题，不采购。
2. **备选与试点设计**：比较“不做”、改流程、简单方案和技术方案，写清基线、指标、成本上限和暂停/回退条件。
3. **桌面验证与单区试点**：先在非生产网络验证设备和协议；通过 `DEC` 批准成本上限后，只采购一个候选区域所需、可退换或可复用的最小数量，再依次开放观察、辅助和自动执行。
4. **评估与方案决策**：将实用性、可靠性、体验、运维、价值和信任数据与基线比较，在 `DEC` 记录中选择推广、修改再试或停止。
5. **分区展开与验收移交**：试点通过推广决策后才进行批量采购和正式施工，所有变更留痕，按正常、异常、离线、人工覆盖和回滚验收。
6. **30/90 天效果复查**：核对工单、人工覆盖、舒适度、维护工时和成本，不达标时继续优化或退役。
