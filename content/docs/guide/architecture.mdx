## 五个信任边界

- **办公网络**：员工电脑和日常协作服务，不直接接受 IoT 设备主动访问。
- **IoT 网络**：传感器和非关键终端；只开放完成业务所需的最小目的地址、端口和方向。
- **自动化服务区**：Home Assistant、消息总线和复杂流程编排；采用独立身份、访问控制和日志。
- **管理区**：网络与控制设备管理面；仅授权运维终端可进入，不与日常上网混用。
- **外部与远端连接**：云服务、供应商支持和站点互联；逐项审批、可停用、可审计。

## 数据流规则

1. 设备默认不能访问办公终端或管理面；跨区访问按“发起方、目的、协议、理由、负责人、失效日期”审批。
2. 本地可完成的控制不因互联网中断而失效；墙面开关和关键控制保持独立。
3. 门禁、消防、应急照明等安全系统不由普通自动化直接控制，只按必要范围提供只读状态。
4. 新增云端、远程支持、摄像/语音或个人级数据流时，先完成安全与隐私评审。
5. 公开记录只保留区域级结果，例如可用率、延迟区间和故障结论；原始日志放在内部受限系统。

## 运维约束

1. 内部基线必须有版本、负责人、最近核验日和恢复演练记录。
2. 网络或策略变更先建立 `CHG`，说明影响、验证与回退；公开记录引用内部变更编号。
3. 配置备份、日志和访问控制清单不得进入公开仓库，密码、私钥和令牌进入专用密钥系统。
4. 每季度验证断网、自动化平台停机、控制器重启和备份恢复，记录脱敏结果。

内部运维基线建议包含资产与端口映射、地址与网络分区、访问控制矩阵、配置备份、远程连接、故障切换和恢复手册；这些内容只在有权限的内部系统中维护。
