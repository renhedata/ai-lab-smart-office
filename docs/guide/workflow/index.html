协作与变更流程

用 GitHub 管理办公室智能化项目中的文档、任务和决策。

三个对象

对象用途示例
Markdown 文档稳定的方案、规范、记录网络方案、设备台账、运维手册
GitHub Issue一项待决、待做或待验收的工作采购会议室传感器、修复 AP 覆盖盲区
Pull Request对文档/配置的可审核变更合并新的 VLAN 规划与交换机配置

推荐状态

想法 → 待评审 → 已批准 → 执行中 → 待验收 → 已完成

以下情况必须新建 Issue：新增费用、改变设备型号、变更布线/电力、自动化规则变更、现场发现问题、验收不通过。

GitHub Projects 字段

在组织级 Project 建立以下字段：

  • 状态：想法、待评审、已批准、执行中、待验收、已完成
  • 区域：前台、办公区、会议室、机房/弱电间、公共区
  • 系统：网络、照明、环境、安防、影音、自动化、文档
  • 预算 与 实际金额
  • 计划完成日、负责人、供应商

GitHub Projects 可把相同项目数据切换为表格、看板和路线图，因此无需复制多份进度表。GitHub 官方说明

提交约定

  • 一个 Pull Request 聚焦一个可描述的变更。
  • 现场照片、设备型号、Issue 编号写入提交说明或文档。
  • 合并前至少由一位了解现场的人复核。
  • 不提交密码、密钥、门禁凭证和个人敏感信息。
