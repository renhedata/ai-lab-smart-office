这不是少数人挑设备的项目。办公室里的任何人都可以提出问题、补充事实、参加试点或反对一个方案；项目组必须回应，并说明采纳、试验、暂缓或拒绝的理由。

<Callout type="warn" title="项目目前仍在准备期">

在指定项目协调人、公司内部快速反馈渠道和首个试点负责人之前，本页是可执行规则，不代表讨论机制已经有人日常运营。

</Callout>

普通使用问题先走公司内部快速反馈渠道；愿意公开讨论且有 GitHub 账号时，可使用 General Discussion。协调人完成合并、脱敏和核实后，再建立正式 `NEED` Issue；`feedback.yml` 只用于已有关联试点的执行反馈，不是第二个普通入口。公司应在已有的飞书、企业微信、钉钉、表单或纸质卡片中选一个作为低门槛入口。代录时标注“来自内部渠道”，缺省不公开姓名和原始聊天截图。

### 30 秒反馈格式

```text
地点：哪个房间或区域？
情况：当时正在做什么，发生了什么？
频率：第一次 / 偶尔 / 每周 / 几乎每天
影响：不舒服、浪费时间、无法完成、安全隐患或其他
期望：你希望下次变成什么样？
```

不知道解决方案也完全正常。“D 会议室演示前要花 3 分钟调灯和窗帘”比“应该买一套 AI 会议系统”更容易验证。

## 共创章程

### 我们要解决什么

- 高频、明确的办公不便，例如会议准备、灯光舒适、空气质量、设备忘关和故障定位。
- 可以通过现场观察、工单、系统数据或员工反馈验证的问题。
- 能小范围试点、保留人工操作并且失败后能撤回的改进。

### 我们不做什么

- 不为了展示“酷”而默认采购；先比较不改造、改流程、简单机械/电气方案和自动化方案。
- 不用存在传感器、门禁、Wi-Fi、会议或环境数据暗中评价个人考勤、绩效或工作强度。
- 不让网络、云服务或自动化主机成为灯光、窗帘和关键设备的唯一操作路径。
- 不让“多数人点赞”压过安全、隐私、无障碍需求或少数人群的真实高影响问题。

### 每位参与者应得到什么

| 承诺 | 默认时限 |
| --- | --- |
| 确认已收到，并给出记录编号 | 2 个工作日内 |
| 判断是故障、需求、试点候选还是不在范围 | 每周分流 |
| 公开当前状态、负责人和下一步；暂不做时说明理由 | 10 个工作日内 |
| 汇总“听到什么、验证了什么、做了什么” | 每月一次 |

时限是项目启动后的默认承诺，不意味着每条建议都会实施。超时时应主动说明阻塞项和下次更新日期。

## 谁参与，谁决定

| 角色 | 人员选择 | 责任 |
| --- | --- | --- |
| 全体员工 | 任何部门和岗位 | 提问题、补事实、参加试点、查看结果 |
| 共创小组 | 6～10 人，覆盖不同部门、空间和技术态度，每半年轮换 | 核实问题、比较备选、参加试点验收 |
| 项目协调人 | 由发起人明确指定 | 代录非 GitHub 反馈、分流、催办和发布月度回顾 |
| 专业负责人 | 行政/设施、IT/网络、电气、采购、信息安全/隐私 | 给出事实、约束、成本、风险和运维边界 |
| 最终决策人 | 预算、安全和用工责任必须有明确授权 | 选择试点/推广/停止，对理由和后果负责 |

“全员共创”代表每个人有知情、表达、被回应和查看依据的权利，不代表所有安全、预算和法律责任都由点赞或投票决定。

## 一条建议如何闭环

```text
新提交 → 待核实 → 已验证需求 → 待设计 → 试点中
                                              ↓
                         已推广 / 继续迭代 / 暂缓 / 拒绝 / 已退役
```

每次状态变化都留下日期、负责人和原因。拒绝或退役的建议不删除；它们也是项目知识，可以防止团队重复走同一条弯路。具体编号、评分和试点卡见[需求、试点与决策记录](/docs/management/records/)。

## 实用性的五道门

一个方案在采购或施工前，必须能回答：

1. **问题真实吗**：有发生频率、受影响人群、现场观察或其他证据吗？
2. **更简单的办法呢**：改流程、标识、传统开关或修复现有设备能解决吗？
3. **失败了怎么办**：人工操作、离线使用、回滚和暂停条件都明确吗？
4. **谁来长期管**：升级、换电池、故障、备份、保修和供应商退出有负责人吗？
5. **能证明更好吗**：试点前有基线，试点后有任务成功、误动作、舒适度、维护量和成本数据吗？

其中任何一道门没有答案，都先记录待确认项，不进入批量采购。

## 信息与隐私边界

| 层级 | 可记录的例子 | 存放位置 |
| --- | --- | --- |
| 可公开共创 | 使用问题、脱敏后的区域、备选方案、预算区间、聚合指标、决策理由 | 公开文档、Discussion 和 Issue |
| 公司内部 | 精确资产与网络拓扑、固件版本、门禁/摄像区域、现场照片、供应商合同、原始传感器日志 | 有权限的内部系统或私有仓库 |
| 禁止进入项目文档 | 密码、令牌、私钥、门禁凭证、未经必要性评估的个人轨迹/录音/人脸数据 | 不得提交；凭证使用专用密钥管理系统 |

任何新的摄像头、麦克风、人脸/指纹、个人位置轨迹、健康数据或用于人员评价的自动化，必须在试点前进入隐私/法务评审，明确目的、最小数据、保存期、访问人、替代方式和删除日期。
