## 四个对象

| 对象 | 用途 | 示例 |
| --- | --- | --- |
| Markdown 文档 | 稳定的方案、规范、记录 | 网络方案、设备台账、运维手册 |
| GitHub Issue | 一项待决、待做或待验收的工作 | 采购会议室传感器、修复 AP 覆盖盲区 |
| ADR 决策记录 | 重要选择的背景、取舍、结论和回滚依据 | 选择 IoT 网络隔离方式、确定本地控制策略 |
| Pull Request | 对文档/配置的可审核变更 | 合并新的 VLAN 规划与交换机配置 |

ADR 是仓库内的 Markdown 文档，但有独立的档案位置：所有实际记录统一放在 [`content/docs/decisions/`](/docs/decisions/)。每份 ADR 关联其 Issue；批准后，方案页、图纸、台账和实施任务再链接回该 ADR。创建方法见[决策记录规范](/docs/guide/decision-log/)。

## 推荐状态

`想法 → 待评审 → 已批准 → 执行中 → 待验收 → 已完成`

以下情况必须新建 Issue：新增费用、改变设备型号、变更布线/电力、自动化规则变更、现场发现问题、验收不通过。

## GitHub Projects 字段

在组织级 Project 建立以下字段：

- `状态`：想法、待评审、已批准、执行中、待验收、已完成
- `区域`：前台、办公区、会议室、机房/弱电间、公共区
- `系统`：网络、照明、环境、安防、影音、自动化、文档
- `预算` 与 `实际金额`
- `计划完成日`、`负责人`、`供应商`

GitHub Projects 可把相同项目数据切换为表格、看板和路线图，因此无需复制多份进度表。[GitHub 官方说明](https://docs.github.com/en/issues/planning-and-tracking-with-projects)

## 提交约定

- 一个 Pull Request 聚焦一个可描述的变更。
- 现场照片、设备型号、Issue 编号写入提交说明或文档。
- 合并前至少由一位了解现场的人复核。
- 不提交密码、密钥、门禁凭证和个人敏感信息。
