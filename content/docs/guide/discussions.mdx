项目的开放讨论统一放在 [GitHub Discussions](https://github.com/renhedata/ai-lab-smart-office/discussions)。打开页面后登录 GitHub，即可发起话题、回复他人的问题或订阅感兴趣的讨论。每篇文档末尾还设有独立的“讨论本文”评论区；它会将该页的留言归到专属 Discussion 中。

<Callout title="从哪里进入">

文档站顶部的“讨论”和每份文档标题下方的“项目讨论”都会打开跨页面的项目讨论区；文档末尾的“讨论本文”仅讨论当前页面。站内不保存账号信息，身份验证完全由 GitHub 处理。

</Callout>

## 什么时候用讨论

| 情况 | 使用方式 |
| --- | --- |
| 想评论某一篇文档、补充错误或追问某段内容 | 在该文档末尾的“讨论本文”留言 |
| 想听取建议、比较方向或分享跨页面经验 | 发起 GitHub Discussion |
| 已有明确范围、负责人和完成条件的工作 | 建立或关联 GitHub Issue |
| 已形成会影响预算、施工、网络或长期维护的选择 | 新建 ADR，并链接相关讨论和 Issue |
| 已确认的方案、规范或验收结果 | 更新项目文档，并通过 Pull Request 审核 |

讨论用于形成共识，不代替任务跟踪或正式决策。讨论中达成的结论，应同步到对应 Issue、ADR 或方案页面，避免只留在评论里。

## 发起高质量讨论

1. 先搜索已有讨论、Issue 和文档，避免重复提问。
2. 标题写清区域或系统，例如“D会议室：窗帘电机供电路径的两种方案”。
3. 说明背景、已知约束、备选方向，以及希望大家回答的问题。
4. 附上可公开的图纸、照片、日志或文档链接；不要发布密码、令牌、门禁凭证、个人敏感信息或未脱敏的现场资料。
5. 讨论形成结果后，链接或新建 Issue；若结果是重要取舍，再按[决策记录规范](/docs/guide/decision-log/)归档 ADR。

## 讨论后的闭环

```text
提出问题或建议
        ↓
GitHub Discussion 收集事实与意见
        ↓
需要执行？ ── 是 → GitHub Issue 分配负责人和验收条件
        ↓
重要取舍？ ── 是 → ADR 固化背景、决定与回滚方式
        ↓
Pull Request 审核文档或配置变更
```
