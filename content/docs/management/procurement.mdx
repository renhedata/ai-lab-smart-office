## 采购前确认

- 需求是否已验证，并且已比较“不做”、改流程或简单设备？
- 是否满足现有协议、网络、安全与供电条件？
- 是否有本地控制、离线可用或开放接口？
- 断网、自动化平台停机和断电恢复后的行为是否已实测？
- 是否支持稳定固件更新、备份和恢复，并明确安全支持结束日？
- 数据能否导出，云端/子处理商/保存期是否清楚，合同结束时能否验证删除？
- 是否已将耗材、安装辅料、售后和替换成本计入预算？

只有关联 `NEED`、通过实用性硬门槛、写清试点指标与回退方式并由 `DEC` 批准成本上限的设备才进入试点采购。D 会议室是当前推荐候选，并非已批准范围；无论最终选择哪里，首轮都只买一个区域闭环所需、可退换或可复用的最小数量，不用“后续反正要装”为理由提前批量下单。批量采购必须等待试点评估和推广决策。

公开采购 Issue 只保留需求编号、能力要求、预算区间、脱敏比较结论和内部采购记录编号，不粘贴报价单、合同、联系人、订单、精确部署位置或网络配置。若选型会改变网络边界、供电/施工方式、控制策略、长期维护成本或预算上限，应另建 `DEC` 记录说明备选、理由和影响，并同步更新相关方案页面。

## 公开采购记录字段

| 字段 | 示例 |
| --- | --- |
| 关联记录 | `NEED-42`、`DEC-57`、内部采购记录编号 |
| 设备类别与能力 | 区域存在传感器 / 本地接口、断网可用 |
| 使用范围 | D 会议室试点；不写精确点位和端口 |
| 比较结论 | 预算区间、关键差异、未选择理由 |
| 数据与云端 | 数据类别、目的、是否出网、保存期结论 |
| 生命周期 | 安全支持期限、替代与退出结论 |
| 状态 | 待比较、已批准、试点中、采用、退役 |

## 内部资产台账字段

资产编号、序列号、MAC/IP/VLAN/端口、精确点位、供应商与订单、保修凭证、配置备份位置、固件版本和退役处置必须保存在有权限的内部系统。公开 Issue 只引用内部记录编号和脱敏后的到货、验收结果，二者由采购或资产负责人维护关联。
