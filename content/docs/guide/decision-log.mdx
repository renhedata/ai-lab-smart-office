title: 决策记录
description: 说明何时建立 ADR、如何编写，以及它在文档库中的唯一存放位置。
---

决策记录采用 ADR（Architecture Decision Record）形式。它不是任务清单，也不是方案正文：它用来保留一个重要选择的背景、备选方案、结论和后续影响，让接手项目的人能追溯“为什么这样做”。

## 放在哪里

每一份实际 ADR 都放在 [`content/docs/decisions/`](/docs/decisions/) 目录，一份文件对应一个决定：

```text
content/docs/
├── guide/                 # 工作方法与协作规范
│   └── decision-log.mdx   # 本页：怎样记录决策
└── decisions/             # 实际决策档案的唯一位置
    ├── index.mdx          # 档案入口、模板与登记规则
    ├── meta.json          # 左侧导航顺序
    └── YYYY-MM-DD-主题.mdx
```

文件名采用 `YYYY-MM-DD-主题.mdx`，例如 `2026-08-03-iot-vlan-isolation.mdx`。目录保持扁平、按日期命名；无论 ADR 是提议、批准还是已替代，都不要因为状态变化而移动或重命名文件，以免外部链接失效。

创建文件后，要把不带扩展名的文件名登记到 `content/docs/decisions/meta.json`，最新记录排在 `index` 后面。文档站将把它显示在“决策档案”分组中。

<Callout title="不要把 ADR 放到其他地方">

`guide/` 只放规范和教程；Issue 只跟踪待办、讨论和负责人；方案页只描述当前采用的设计。重要选择的依据和取舍必须以 ADR 保存在 `decisions/`，并从这些对象互相链接。

</Callout>

## 什么时候建立

出现以下任一情况，就建立或更新一份 ADR：

- 会影响预算、采购、工期、体验、安全、施工或后续维护。
- 在两个或以上可行方案之间取舍，例如协议、拓扑、供电方式、设备型号或自动化策略。
- 会改变多个房间、系统或责任人的边界。
- 需要明确回滚方法，或未来很可能有人追问选择理由。

纯粹的实施任务、现场待确认项或一次性故障，先建 Issue；当 Issue 形成需要长期保留的选择时，再关联 ADR。

## 模板

在 `content/docs/decisions/` 中新建文件，并使用以下模板。编号可采用日期加序号，例如 `ADR-20260803-01`；同一编号只使用一次。

```md title="content/docs/decisions/2026-08-03-iot-vlan-isolation.mdx"
---
title: ADR-20260803-01：IoT 设备 VLAN 隔离
description: 控制设备使用独立 VLAN，并只开放所需访问路径。
---

| 字段 | 内容 |
| --- | --- |
| 日期 | 2026-08-03 |
| 状态 | 提议 / 已批准 / 已替代 |
| 决策人 | 姓名或角色 |
| 关联 Issue | #编号或链接 |
| 影响范围 | 房间、系统、设备或施工项 |

## 背景

当前问题、约束与目标。

## 备选方案

1. 方案 A：优点 / 缺点 / 成本
2. 方案 B：优点 / 缺点 / 成本

## 决定

最终选择及原因。

## 影响、实施与回滚

对预算、施工、运维和现有系统的影响；实施前置条件；若失败如何恢复。

## 验证与关联文档

验收方式、证据链接、需要同步更新的方案页、台账或图纸。

## 变更记录

- YYYY-MM-DD：创建，状态为“提议”。
- YYYY-MM-DD：批准/替代；说明批准人或替代 ADR 链接。
```

## 状态与维护规则

| 状态 | 含义 | 后续动作 |
| --- | --- | --- |
| 提议 | 备选方案仍在评审，尚不能作为施工或采购依据 | 关联 Issue，补齐成本、风险和验收方式 |
| 已批准 | 项目负责人确认，可据此更新方案和推进实施 | 在对应方案、图纸、台账和 Issue 中链接此 ADR |
| 已替代 | 原结论不再适用，但历史理由仍须保留 | 不删除原文件；写明替代原因并链接新的 ADR |

已批准的 ADR 不应被悄悄改写成新结论。若决定本身改变，新增一份 ADR，并在新旧记录中互相链接；原记录只更新状态和变更记录。

<Callout>

决策记录不追求长篇大论，关键是让半年后接手项目的人明白：当时为什么这样做、影响什么、由谁确认，以及现在是否仍有效。可从[决策档案](/docs/decisions/)查看所有已登记的 ADR。

</Callout>
